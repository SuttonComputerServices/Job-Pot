# Job Pot Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Self-hosted multi-user web app that finds jobs, scores fit, auto-applies where possible, and tracks employer email responses.

**Architecture:** FastAPI + Jinja2 server-rendered UI and a separate worker loop sharing one SQLite DB. Connectors per site behind one interface. Secrets Fernet-encrypted with per-user HKDF keys.

**Tech Stack:** Python 3.12, FastAPI, SQLAlchemy 2, Jinja2, argon2-cffi, cryptography, pyotp, segno, httpx, pypdf, python-docx, Playwright, pytest.

**Spec:** `docs/specs/2026-10-27-job-pot-design.md`

## Global Constraints
- Package `jobpot/` at repo root; tests in `tests/`; run `pytest -q`.
- Data dir `JOBPOT_DATA` (default `./data`); DB `sqlite:///<data>/jobpot.db` unless `DATABASE_URL`.
- No default admin password anywhere; setup needs the one-time token.
- Every POST checks CSRF; every user row lookup goes through `get_owned`.
- Palette: no blue/purple/red. No emoji, no gradients. No external CDN (CSP `default-src 'self'`).
- Code style: ponytail (minimal); `shortcut:` comments for known limits.

## Review Focus
1. Uploading a scanned/image-only PDF → no text; resume page must say so, not crash. (Task 5 test)
2. IMAP message with no text/plain part, odd charsets → body still extracted. (Task 6 test)
3. Job site HTML/API shape changes → connector logs `last_error`, worker keeps going for other users. (Task 7 test)
4. Username change to an existing name (any case) → rejected. (Task 3 test)
5. Ollama down/slow → AI features fall back to rules with a visible note, page doesn't hang (timeout). (Task 8 test)
